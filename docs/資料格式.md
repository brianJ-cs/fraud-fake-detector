# 資料格式（草稿，請確認）

兩人共用的格式。改這份要兩個人都同意。所有檔案用 UTF-8、JSON Lines（一行一筆）。

## 1. 訊息 `data/messages.jsonl`（吳則顯產出）

```json
{
  "id": "cofacts 的 article id",
  "text": "整理過、去掉個資的訊息內容（電話換成 [電話]、帳號換成 [帳號]）",
  "urls": ["https://..."],
  "cofacts_reply_type": "RUMOR | NOT_RUMOR | OPINIONATED | NOT_ARTICLE | null",
  "auto_label": "scam | rumor | normal",
  "human_label": "scam | rumor | normal | null",
  "split": "dev | test"
}
```

- `auto_label`：用 Cofacts 原本的分類自動對應出來的。
- `human_label`：我們人工標的（300 則），還沒標就填 null。
- `split`：`dev` 用來調提示詞和門檻；`test` 是實驗用的，只正式跑一次。

## 2. 分類結果（吳則顯 → 江柏賢）

```json
{
  "id": "訊息 id",
  "method": "llm_zero_shot | llm_few_shot | svm",
  "label": "scam | rumor | normal",
  "confidence": 0.87,
  "reason": "一兩句說明為什麼",
  "needs_verification": true,
  "suspicious_spans": [
    {"text": "加老師LINE", "category": "導流私訊", "start": 12, "end": 18}
  ],
  "risk": "high | medium | low | null",
  "model": "模型名稱",
  "prompt_version": "v1"
}
```

- `needs_verification`：只要訊息裡有可以查證的說法就填 true（謠言一定是 true；詐騙訊息如果也冒用了假消息，例如「衛福部說…」，也填 true）。查證那邊只處理這個欄位是 true 的訊息。
- `suspicious_spans`、`risk`：只有 `label = scam` 時才填，其他情況給 `[]` 和 `null`。
- `start` / `end`：在 `text` 裡的字元位置。必須滿足 `text[start:end] == span.text`，不符合的 span 要丟掉。
- 可疑句子的 8 類（草稿，請吳則顯確認）：
  導流私訊、保證獲利、急迫限時、冒充官方或名人、要求匯款、索取個資或驗證碼、可疑連結或下載、中獎或免費贈品

## 3. 查證結果（江柏賢產出）

```json
{
  "id": "訊息 id",
  "mode": "db_only | web_only | hybrid",
  "claims": [
    {
      "claim": "隔夜開水會被衛福部罰款",
      "verdict": "false | true | misleading | unverifiable",
      "explanation": "根據證據說明",
      "sources": [
        {"title": "...", "url": "...", "from": "db | web", "snippet": "..."}
      ]
    }
  ],
  "overall_verdict": "false | true | misleading | unverifiable",
  "elapsed_sec": 4.2
}
```

- 每則訊息最多拆出 3 個說法（`claims`）。
- 沒有來源就不能判 true 或 false，只能判 `unverifiable`。
